# Стадія 5 — Полірування + документація

> Самодостатня інструкція. Перед початком прочитай [PLAN.md](PLAN.md). Передумова: Стадії 1–4 завершені (повний новий shell, дашборд, ribbon скрізь, Settings hub).

## Мета

Завершальне шліфування UX, чистка мертвого коду/стилів, документація користувача. Після цієї стадії гілка готова до PR у master.

## Завдання

### Персистенція стану вікна
- Зберігати у `Data/UserSettings.json` (через наявний `UserSettingsService`): розмір/позицію вікна (з валідацією, що вікно влазить у поточний екран), стан maximized, `IsSidebarCollapsed`.
- Відновлювати при старті в `App.OnFrameworkInitializationCompleted`/MainWindow.

### Empty states
- Дашборд без історії: дружній плейсхолдер у таблиці («Ще немає документів — створіть перший звіт») + підказка на картки.
- Дашборд без обраних: підказка про зірочку.
- History без записів / без збігів фільтра: розрізнити два повідомлення.
- DocumentTabStrip при 0 документів — прихований (перевірити, з'явилось у Стадії 1).

### Глобальний пошук — flyout (опційно, якщо лишився час)
- Під полем пошуку — Popup з топ-5 збігів з `IReportHistoryRepository.GetIndex()` (тип + № + дата); Enter — повний перехід на History, клік по збігу — одразу відкрити запис через ReportTabFactory.

### Чистка
- Видалити мертві стилі/ресурси: `ColorDismantlingBackground` (Wheat-фон AssetDismantlingView — на новій палітрі виглядає чужорідно; замінити нейтральною поверхнею), старі palette-кольори #cc4d11, невикористані стилі `StackPanel.buttons`, залишки `Button.CloseTab`, невикористані іконки.
- `grep`-перевірки: `HomePage`, `CloseTab`, `Classes="buttons"`, `cc4d11`, `Wheat` — усе має бути порожнім (або свідомо лишеним).
- TODO у MainWindowViewModel про dispose вкладок: при закритті документа відписувати події (перевірити витоки підписок ReportTabFactory/MainWindowViewModel).

### Accessibility / дрібний UX
- Прохід усіма екранами в обох темах: контраст текстів, фокус-стани, читабельність бейджів.
- Tooltips на іконкових кнопках ribbon і сайдбара (особливо у згорнутому стані сайдбара — tooltip обов'язковий).
- Tab-порядок на формах редакторів.
- Перевірити DPI-скейлінг зони заголовка (системні кнопки/відступ).

### Документація
- README.md: оновити/додати українську секцію про новий інтерфейс через skill `update-docs` (скріншоти: дашборд, редактор з ribbon, темна тема).
- Якщо README має застарілі скріншоти старого UI — замінити.

### macOS smoke-тест (вручну, перед релізом)
- ExtendClientArea: «світлофори» не перекриваються сендвічем; drag заголовка; повноекранний режим.
- Шрифти/розміри ribbon.

## Критерії готовності та перевірка

1. `dotnet build` + повний `dotnet test` зелені.
2. Повний прохід skill `ui-verify` (обидві теми): дашборд → створення звіту → редагування → чернетка → формування → історія → пошук → довідники → налаштування → рестарт (тема, вікно, сайдбар, обрані відновлені).
3. `dotnet publish` win-x64 Release збирається.
4. Оновити чекбокс Стадії 5 у PLAN.md і memory `project_ui_redesign_phases.md`; гілка готова до PR.
